Executive Summary

TalkSign is Talkpush's native document signing solution designed to replace DocuSign within the onboarding workflow. Rather than replicating DocuSign's full feature set, TalkSign focuses exclusively on the high-volume hiring use case: recruiters configure document templates for a campaign, candidates receive a unique signing link, auto-filled fields populate from their Talkpush profile, and remaining fields are completed and signed by the candidate on any device.

Key differentiator: The signing link is stored as a candidate attribute in Talkpush, enabling it to be sent via any channel the platform already supports — WhatsApp, SMS, Messenger, email — through existing automation workflows. No separate sending infrastructure is needed.

Problem Statement

Current Pain Points with DocuSign

Cost

  • Per-envelope fees ($1.50–$2.50) add up significantly in high-volume hiring (1,000+ hires/month)
  • Enterprise licensing costs for API access
  • Additional charges for premium features like bulk send

Integration Friction

  • Candidate data must be synced to DocuSign then back — creating latency and sync errors
  • Signing links are generated externally and must be imported back to Talkpush
  • Status updates require webhook management with a third-party system

Feature Mismatch

  • DocuSign is built for general e-signatures, not optimized for recruitment onboarding
  • Talkpush uses ~20% of DocuSign's features but pays for 100%
  • No native understanding of campaigns, candidate profiles, or hiring workflows

Candidate Experience

  • Candidates are redirected to DocuSign's UI — a jarring experience outside the Talkpush flow
  • DocuSign requires consent screens and account prompts that add friction
  • No branding continuity between Talkpush onboarding and signing

Module 3: Data Mapping & Auto-Fill

Connect document fields to Talkpush candidate attributes or candidate input

3.1 Data Source Configuration

Every field placed on a template must have a data source defined. This determines whether the field is auto-filled from the candidate's Talkpush profile or left for the candidate to complete.

IDRequirementPriorityDescription
TS-020 Auto-Fill from Talkpush Attributes P0 For any text, number, date, dropdown, or read-only field, the admin can select a Talkpush candidate attribute as the data source. When the signing session starts, TalkSign fetches the candidate's current attribute values and populates the fields automatically. Available attributes include all standard and custom fields in the candidate profile.
TS-021 Candidate Input Fields P0 Fields marked as "Candidate Input" are left blank for the candidate to fill in during the signing session. Signature and Initials fields are always candidate input. For all other field types, the admin chooses: auto-fill (attribute) or candidate input.
TS-022 Attribute Picker UI P0 When "Auto-fill from attribute" is selected, a searchable dropdown shows all available Talkpush candidate attributes grouped by category (Personal, Contact, Employment, Custom, Campaign-specific). Shows attribute name, type, and sample value.
TS-023 Auto-Fill with Editable Override P0 Admin can configure auto-filled fields as either read-only (candidate cannot change) or editable (pre-filled but candidate can modify). Default: read-only for auto-filled fields.
TS-024 Static Value Fields P0 A field can be set to a static (hardcoded) value that is the same for all candidates using this template (e.g., company name, company address, policy version number). Rendered as read-only text in the document.
TS-025 Missing Attribute Handling P0 If an auto-fill attribute is empty or missing for a candidate: (1) If the field is required, the candidate is prompted to fill it in manually. (2) If optional, the field is left blank. (3) Admin can define a default/fallback value for missing attributes.
TS-026 Attribute Writeback P1 When a candidate fills in or modifies a field during signing, the value can be written back to the candidate's Talkpush profile attribute. Admin configures this per field. Useful for collecting data like emergency contact or bank details that should persist in the candidate profile.

Module 4: Candidate Signing Experience

Mobile-first, frictionless signing flow with Talkpush branding

4.1 Signing Flow Requirements

IDRequirementPriorityDescription
TS-030 Mobile-First Responsive UI P0 The signing experience must be optimized for mobile devices first (WhatsApp is the primary delivery channel). Responsive layout that works on any screen size. Touch-friendly controls. No pinch-to-zoom required to interact with fields.
TS-031 No Account Required P0 Candidates must NOT need to create an account or log in to sign documents. The signing link itself is the access token. No friction — open link, review, fill, sign.
TS-032 Guided Field-by-Field Flow P0 On mobile, instead of showing the full document with small fields, present a guided step-by-step flow: (1) show all auto-filled read-only fields for review, (2) present each candidate-input field one at a time in large, easy-to-use format, (3) signature/initials capture as the final step. A progress bar shows completion status. On desktop, the full document view is also available as an option.
TS-033 Electronic Signature Capture P0 Two signature methods: (1) Draw — finger/stylus on touch screen or mouse on desktop, rendered on a signature pad canvas. (2) Type — type name and select from 4 signature font styles. Both produce a signature image embedded in the final PDF. Candidate can redo before confirming.
TS-034 E-Disclosure Consent P0 Before signing, candidates must consent to electronic records and signatures (ESIGN Act / UETA compliance). Present a clear disclosure: "By proceeding, you agree to sign electronically. Your electronic signature has the same legal validity as a handwritten signature." Candidate must actively consent (checkbox + continue).
TS-035 Document Review Before Signing P0 Candidates can view the complete document (all pages) with auto-filled data before signing. PDF viewer with zoom, scroll, page navigation. Auto-filled fields are visually highlighted. On mobile, option to download or view full PDF.
TS-036 Multi-Document Signing Session P0 When a campaign requires multiple documents, the candidate signs them in a single session. A document list/stepper shows which documents are pending, in progress, and completed. Candidate progresses through each document sequentially. Session is complete when all documents are signed.
TS-037 Save & Resume Later P1 If a candidate partially completes the signing session (fills some fields but doesn't sign), their progress is saved. When they return to the same link, they resume where they left off. Partially completed fields are preserved.
TS-038 Decline to Sign P0 Candidate can decline to sign a document. Requires selecting a reason from a list (disagree with terms, need more time, want to speak with recruiter, other) and optional free-text comment. Declining updates the document status and notifies the recruiter.
TS-039 Confirmation & Download P0 After signing all documents, show a confirmation screen with: success message, list of signed documents, option to download a copy of each signed document (PDF), and a "You may close this window" message. Also send a confirmation to the candidate's email (if available) with signed PDFs attached.
TS-040 Talkpush Branding P0 The signing UI uses Talkpush branding (or client white-label branding if configured). Logo, colors, and tone match the Talkpush onboarding experience. No third-party branding is shown.
TS-041 Multi-Language Support P1 The signing UI (labels, instructions, buttons) supports multiple languages. Language is auto-detected from the candidate's profile or browser locale. Documents themselves remain in their uploaded language — the UI chrome is translated.
TS-042 Identity Verification (Optional) P2 For high-security documents, admin can require identity verification before signing: (1) SMS OTP sent to candidate's phone on file, (2) email verification link, or (3) knowledge-based question (date of birth or last 4 of SSN). Configurable per template.

Module 5: Signing Link Generation

Unique signing URLs stored as candidate attributes for omnichannel delivery

5.1 Link Generation Requirements

IDRequirementPriorityDescription
TS-050 Unique Signing URL per Candidate P0 When a candidate reaches the signing stage in a campaign workflow, the system generates a unique, cryptographically secure URL. Format: https://sign.talkpush.com/{token} where token is a non-guessable, URL-safe string (e.g., UUID v4 or 32-char random base62). One URL covers all documents the candidate needs to sign for that campaign.
TS-051 Store as Candidate Attribute P0 The generated signing URL is automatically stored as a candidate attribute (e.g., signing_url) in the candidate's Talkpush profile. This allows any Talkpush automation (WhatsApp message, SMS, email, chatbot response) to reference and send the link using the standard attribute merge syntax: {{signing_url}}.
TS-052 Signing Status Attribute P0 In addition to the URL, the following candidate attributes are maintained and updated in real-time:
  • signing_status — overall status: pending, in_progress, completed, declined, expired, voided
  • signing_completed_at — timestamp when all documents were signed
  • signing_documents_total — number of documents to sign
  • signing_documents_completed — number signed so far
TS-053 Link Expiration P0 Signing links have a configurable expiration period (default: 7 days, configurable per campaign: 1-90 days). After expiration, the link shows a "This signing link has expired" message with instructions to contact the recruiter. Status updates to expired.
TS-054 Link Regeneration P0 Recruiters can regenerate an expired or voided signing link from the candidate profile. The old link is invalidated and a new one is created. The signing_url attribute is updated. If the candidate had partial progress, admin chooses: keep progress or restart.
TS-055 Link Voiding P0 Recruiters can void (cancel) a signing link if the offer is rescinded or documents need to change. Voided links show a "This signing request has been cancelled" message. If the candidate was mid-signing, they cannot continue.
TS-056 Automatic Generation via Workflow P0 Signing links are automatically generated when a candidate reaches a specific workflow stage (configurable trigger). No manual action required. The workflow engine triggers TalkSign to create the signing session and populate the attribute.
Key design decision: By storing the signing link as a candidate attribute, Talkpush's existing messaging infrastructure handles delivery. The recruiter can send the link via WhatsApp template, SMS, email, chatbot — whatever channel the candidate is already on. No new sending infrastructure is needed in TalkSign.

Module 6: Status Tracking & Audit Trail

Real-time visibility and legally admissible audit records

6.1 Status Tracking

IDRequirementPriorityDescription
TS-060 Real-Time Status Dashboard P0 Campaign-level view showing all candidates and their signing status. Filterable by status (pending, viewed, in progress, completed, declined, expired). Sortable columns. Bulk actions (resend reminder, void).
TS-061 Per-Candidate Status P0 In the candidate profile, show detailed signing status per document: document name, status (pending / viewed / signed / declined), timestamp of last activity, and link to view the signed PDF (if complete).
TS-062 Document-Level Status States P0 Each document tracks these states:
  • Pending — link generated, candidate hasn't opened it yet
  • Viewed — candidate opened the link and viewed the document
  • In Progress — candidate started filling in fields (partially completed)
  • Completed — candidate signed the document
  • Declined — candidate explicitly declined to sign
  • Expired — signing link expired before completion
  • Voided — recruiter cancelled the signing request

6.2 Audit Trail

IDRequirementPriorityDescription
TS-065 Immutable Event Log P0 Every action on a signing session is logged with immutable, append-only records:
  • Signing session created (who, when, which documents)
  • Link sent / delivered (channel, timestamp)
  • Link opened (timestamp, IP address, user agent, device type)
  • E-disclosure consent given (timestamp, IP)
  • Each document viewed (timestamp, IP)
  • Each field filled / modified (field name, value, timestamp)
  • Signature captured (method: draw/type, timestamp, IP)
  • Document signed (timestamp, IP, device)
  • Document declined (reason, timestamp)
  • Session completed (timestamp)
  • Signed PDF generated and stored
TS-066 Certificate of Completion P0 For each completed signing session, generate a Certificate of Completion PDF that includes: signer's name and email, list of documents signed, timestamp for each signature, IP address at time of signing, e-disclosure consent record, device and browser info, unique signing session ID, and a tamper-evident hash of the signed documents. This certificate is stored alongside the signed documents and is downloadable by recruiters.
TS-067 Audit Log Viewer P1 In the admin UI, recruiters can view the full audit trail for any signing session. Timeline view showing every event chronologically. Exportable as CSV or PDF for compliance/legal needs.

Module 7: Reminders & Expiration

Automated follow-ups to maximize signing completion rates

IDRequirementPriorityDescription
TS-070 Configurable Reminder Schedule P0 Per campaign, configure an automated reminder schedule for unsigned documents. Define: (1) first reminder (X days/hours after link generation), (2) repeat interval (every X days/hours), (3) maximum number of reminders. Default: first reminder at 24 hours, repeat every 2 days, max 3 reminders.
TS-071 Reminder Delivery via Talkpush P0 Reminders are sent through Talkpush's existing messaging automation, not by TalkSign directly. TalkSign updates the candidate's signing_status attribute and triggers a Talkpush workflow event (e.g., signing_reminder_due). The workflow sends the reminder message via the campaign's configured channel (WhatsApp, SMS, email), including the {{signing_url}} attribute.
TS-072 Expiration Handling P0 When a link expires: status updates to expired, candidate sees expiration message if they try to access, a workflow event signing_expired fires (enabling custom automation — e.g., notify recruiter, send candidate a message, or auto-regenerate link).
TS-073 Pre-Expiration Warning P1 X hours/days before expiration, fire a signing_expiring_soon workflow event. Enables sending an urgent "Your documents expire in 24 hours" message to the candidate.

Module 8: Document Storage & Retrieval

Secure storage of signed documents with easy access

IDRequirementPriorityDescription
TS-080 Signed PDF Generation P0 Upon signing, generate the final PDF with all fields rendered (auto-filled values, candidate inputs, signatures, initials, dates). The signed PDF is a flattened, non-editable PDF. A tamper-evident hash (SHA-256) is computed and stored with the document.
TS-081 Encrypted Storage P0 All signed documents are stored encrypted at rest (AES-256). Storage location: cloud object storage (AWS S3 or equivalent) with server-side encryption. Access requires authenticated API calls with proper authorization.
TS-082 Retrieval from Candidate Profile P0 Recruiters can view and download signed documents directly from the candidate profile in Talkpush. Each signed document shows: document name, signed date, and a download/preview button. Also available: the Certificate of Completion.
TS-083 Bulk Download P1 Download all signed documents for a candidate as a ZIP archive (includes all signed PDFs + Certificate of Completion). Also available at campaign level: export all completed documents for all candidates.
TS-084 Retention Policy P1 Configurable document retention period per organization. Default: indefinite. Options: 1 year, 3 years, 5 years, 7 years, indefinite. After retention period, documents are securely deleted. 30-day warning before deletion.
TS-085 Candidate Copy Delivery P0 After signing, the candidate receives a copy of their signed documents. Delivery methods: (1) immediate download at end of signing session, (2) email with signed PDFs attached (if email is available), (3) signing link remains accessible (read-only, showing completed documents) for 30 days after signing.

Data Model

Core database schema for TalkSign

Entity Relationship

-- ============================================
-- TALKSIGN DATA MODEL
-- ============================================

-- Document Templates
CREATE TABLE talksign_templates (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id UUID NOT NULL,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    category VARCHAR(50) NOT NULL,
        -- offer_letter, employment_contract, nda, policy,
        -- tax_compliance, benefits, custom
    status VARCHAR(20) NOT NULL DEFAULT 'draft',
        -- draft, active, archived
    version INTEGER NOT NULL DEFAULT 1,
    parent_template_id UUID REFERENCES talksign_templates(id),
    source_pdf_url TEXT NOT NULL,
    source_pdf_hash VARCHAR(64) NOT NULL, -- SHA-256
    page_count INTEGER NOT NULL,
    created_by UUID NOT NULL,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Template Fields (placed on the PDF)
CREATE TABLE talksign_template_fields (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    template_id UUID NOT NULL REFERENCES talksign_templates(id) ON DELETE CASCADE,
    field_type VARCHAR(30) NOT NULL,
        -- signature, initials, text, text_area, number,
        -- date, dropdown, checkbox, radio,
        -- auto_date, read_only, attachment
    label VARCHAR(255) NOT NULL,
    page_number INTEGER NOT NULL,
    position_x DECIMAL(10,4) NOT NULL, -- % from left
    position_y DECIMAL(10,4) NOT NULL, -- % from top
    width DECIMAL(10,4) NOT NULL,      -- % of page width
    height DECIMAL(10,4) NOT NULL,     -- % of page height
    tab_order INTEGER NOT NULL,
    is_required BOOLEAN NOT NULL DEFAULT true,

    -- Data source
    data_source VARCHAR(20) NOT NULL DEFAULT 'candidate_input',
        -- candidate_input, talkpush_attribute, static_value,
        -- computed (signing_date, etc.)
    talkpush_attribute_key VARCHAR(255), -- if data_source = talkpush_attribute
    static_value TEXT,                   -- if data_source = static_value
    computed_type VARCHAR(50),           -- if data_source = computed
    is_editable_when_autofilled BOOLEAN DEFAULT false,
    fallback_value TEXT,                 -- if attribute is missing
    writeback_attribute_key VARCHAR(255), -- write candidate input back to profile

    -- Validation
    validation_rules JSONB,
        -- { "max_length": 100, "pattern": "^[A-Za-z]+$",
        --   "min_value": 0, "max_value": 999999,
        --   "date_format": "MM/DD/YYYY",
        --   "allowed_types": ["pdf","jpg"], "max_file_size_mb": 10 }

    -- Dropdown/Radio options
    options JSONB,
        -- [{"label": "Full-Time", "value": "full_time"}, ...]
    default_value TEXT,

    -- Display
    placeholder_text VARCHAR(255),
    font_size INTEGER DEFAULT 12,

    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Campaign Signing Configuration
CREATE TABLE talksign_campaign_configs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    campaign_id UUID NOT NULL, -- Talkpush campaign ID
    organization_id UUID NOT NULL,
    is_active BOOLEAN DEFAULT true,

    -- Documents to sign (ordered)
    documents JSONB NOT NULL,
        -- [{"template_id": "...", "order": 1}, ...]

    -- Link settings
    link_expiration_days INTEGER NOT NULL DEFAULT 7,

    -- Reminder settings
    reminder_enabled BOOLEAN DEFAULT true,
    reminder_first_after_hours INTEGER DEFAULT 24,
    reminder_repeat_every_hours INTEGER DEFAULT 48,
    reminder_max_count INTEGER DEFAULT 3,

    -- Identity verification
    identity_verification_enabled BOOLEAN DEFAULT false,
    identity_verification_method VARCHAR(20), -- sms_otp, email, knowledge_based

    -- Branding
    custom_logo_url TEXT,
    custom_primary_color VARCHAR(7), -- hex

    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Signing Sessions (one per candidate per campaign)
CREATE TABLE talksign_signing_sessions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    candidate_id UUID NOT NULL,
    campaign_id UUID NOT NULL,
    config_id UUID NOT NULL REFERENCES talksign_campaign_configs(id),
    organization_id UUID NOT NULL,

    -- Link
    token VARCHAR(64) NOT NULL UNIQUE, -- URL token
    signing_url TEXT NOT NULL,

    -- Status
    status VARCHAR(20) NOT NULL DEFAULT 'pending',
        -- pending, viewed, in_progress, completed,
        -- declined, expired, voided

    -- Timestamps
    created_at TIMESTAMPTZ DEFAULT NOW(),
    first_viewed_at TIMESTAMPTZ,
    completed_at TIMESTAMPTZ,
    expires_at TIMESTAMPTZ NOT NULL,
    voided_at TIMESTAMPTZ,
    voided_by UUID,
    voided_reason TEXT,

    -- Counts
    documents_total INTEGER NOT NULL,
    documents_completed INTEGER NOT NULL DEFAULT 0,

    -- Consent
    edisclosure_consented_at TIMESTAMPTZ,
    edisclosure_consent_ip INET,

    -- Identity verification
    identity_verified_at TIMESTAMPTZ,
    identity_verification_method VARCHAR(20),

    -- Reminders
    reminders_sent INTEGER DEFAULT 0,
    last_reminder_sent_at TIMESTAMPTZ
);

-- Signing Documents (one per document in session)
CREATE TABLE talksign_signing_documents (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id UUID NOT NULL REFERENCES talksign_signing_sessions(id),
    template_id UUID NOT NULL REFERENCES talksign_templates(id),
    document_order INTEGER NOT NULL,

    status VARCHAR(20) NOT NULL DEFAULT 'pending',
        -- pending, viewed, in_progress, completed, declined

    -- Filled field values
    field_values JSONB NOT NULL DEFAULT '{}',
        -- { "field_id": {"value": "John", "filled_at": "...",
        --                "source": "auto_fill|candidate"} }

    -- Signature data
    signature_data JSONB,
        -- { "method": "draw|type", "image_url": "...",
        --   "typed_name": "John Doe", "font": "signature-1" }
    initials_data JSONB,

    -- Signed PDF
    signed_pdf_url TEXT,
    signed_pdf_hash VARCHAR(64), -- SHA-256 tamper detection
    certificate_pdf_url TEXT,

    -- Decline info
    declined_at TIMESTAMPTZ,
    decline_reason VARCHAR(100),
    decline_comment TEXT,

    -- Timestamps
    first_viewed_at TIMESTAMPTZ,
    completed_at TIMESTAMPTZ,

    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Audit Trail (immutable, append-only)
CREATE TABLE talksign_audit_log (
    id BIGSERIAL PRIMARY KEY,
    session_id UUID NOT NULL REFERENCES talksign_signing_sessions(id),
    document_id UUID REFERENCES talksign_signing_documents(id),

    event_type VARCHAR(50) NOT NULL,
        -- session_created, link_opened, edisclosure_consented,
        -- document_viewed, field_filled, field_modified,
        -- signature_captured, initials_captured,
        -- document_signed, document_declined,
        -- session_completed, pdf_generated,
        -- reminder_triggered, link_expired, link_voided,
        -- link_regenerated, identity_verified

    event_data JSONB, -- event-specific payload

    -- Context
    ip_address INET,
    user_agent TEXT,
    device_type VARCHAR(20), -- mobile, tablet, desktop

    -- Actor
    actor_type VARCHAR(20) NOT NULL, -- candidate, recruiter, system
    actor_id UUID,

    created_at TIMESTAMPTZ DEFAULT NOW()
);

Security & Compliance

Legal validity and data protection

Legal Compliance

IDRequirementPriorityDescription
TS-090 ESIGN Act & UETA Compliance P0 Electronic signatures must satisfy the U.S. ESIGN Act and Uniform Electronic Transactions Act requirements: (1) intent to sign, (2) consent to do business electronically, (3) association of signature with the record, (4) record retention. The e-disclosure consent + audit trail + signed PDF achieve this.
TS-091 Tamper-Evident Documents P0 Each signed PDF has a SHA-256 hash stored in the database. Any modification to the PDF after signing can be detected by comparing the hash. The Certificate of Completion includes this hash.
TS-092 Data Encryption P0 All documents encrypted at rest (AES-256). All API communication over TLS 1.3. Signing tokens are cryptographically random and non-guessable.
TS-093 Access Control P0 Role-based access: only authorized recruiters/admins within the organization can view signed documents, audit trails, and manage templates. Candidates can only access their own signing session via their unique token.
TS-094 GDPR / Data Privacy P1 Support data subject requests: ability to export all signing data for a candidate, delete signing records upon request (with legal hold exceptions). Consent is recorded for electronic communication.

Candidate Attributes Read & Write Read: Auto-fill fields from candidate profile attributes. Write: Store signing_url, signing_status, signing_completed_at, and other status attributes. Optionally write back candidate-entered values to profile.

Key User Stories

Core user stories with acceptance criteria

Recruiter / Admin Stories

US-01: As a recruiter, I want to upload a PDF and place signature and input fields visually on the document, so that I can create reusable signing templates without technical skills.

  • Can upload PDF up to 25 MB, multi-page supported
  • Drag-and-drop field palette with all supported field types
  • Fields can be repositioned, resized, and configured via properties panel
  • Preview mode shows how the document will appear to candidates
  • Template can be saved as draft and published when ready

US-02: As a recruiter, I want to map document fields to Talkpush candidate attributes, so that documents are auto-filled with candidate information and I don't need to enter data manually.

  • Each field has a data source selector: "Auto-fill from attribute" or "Candidate fills in"
  • Attribute picker shows all candidate attributes grouped by category
  • Auto-filled fields can be set as read-only or editable by candidate
  • Missing attributes show a fallback value or prompt candidate to fill in

US-03: As a recruiter, I want to select which documents a candidate must sign for a specific campaign, so that different roles/locations get the appropriate document set.

  • Campaign configuration screen lists all active templates
  • Recruiter selects and orders the documents for the campaign
  • Can configure link expiration, reminder schedule per campaign
  • Changes to campaign config apply to new signing sessions only (existing sessions unchanged)

US-04: As a recruiter, I want to see a dashboard of all candidates' signing status for my campaign, so that I can follow up on incomplete signatures and track onboarding progress.

  • Campaign dashboard shows all candidates with signing status (pending, viewed, in progress, completed, declined, expired)
  • Filterable and sortable by status, date, candidate name
  • Click on candidate to see per-document detail and audit trail
  • Bulk actions: resend reminder, void, regenerate link

US-05: As a recruiter, I want to download signed documents and the certificate of completion from the candidate's profile, so that I can store them in the employee file or share with HR/legal.

  • Candidate profile shows "Signed Documents" section with download buttons
  • Can download individual signed PDFs or a ZIP of all documents + certificate
  • Certificate of Completion includes signer info, timestamps, IP addresses, tamper-evident hash

Candidate Stories

US-06: As a candidate, I want to open a signing link on my phone, see my information pre-filled, complete any remaining fields, and sign — all in under 60 seconds, so that I can complete my onboarding quickly without frustration.

  • Link opens directly in mobile browser (no app install, no account creation)
  • Welcome screen with e-disclosure consent (one tap)
  • Auto-filled fields are clearly shown as pre-populated
  • Candidate-input fields presented in guided step-by-step flow on mobile
  • Signature capture is large and touch-friendly (draw or type)
  • Confirmation screen with download option

US-07: As a candidate, I want to receive a copy of my signed documents, so that I have my own records of what I signed.

  • Download available immediately after signing
  • Email with signed PDFs sent if email is on file
  • Signing link remains accessible (read-only) for 30 days showing completed documents

US-08: As a candidate, I want to decline to sign a document and provide a reason, so that I can communicate concerns without abandoning the process entirely.

  • Visible "Decline" option on each document (not hidden)
  • Reason selection required (predefined options + free text)
  • Declining one document does not prevent signing others
  • Recruiter is notified immediately when a document is declined

Key interface patterns following the Talkpush Visual Language

Admin: Template Builder

Layout Specification

Candidate: Mobile Signing Experience

Layout Specification

Structure: Full-screen mobile-optimized flow. No navigation chrome — focused on the task.

  • Screen 1 — Welcome: Company logo (or Talkpush if no white-label), "Hi {first_name}, please review and sign your documents", document list with names and count, e-disclosure consent checkbox, "Get Started" CTA (Talkpush Green, full-width).
  • Screen 2 — Document Review: Document name at top, scrollable PDF preview (or summary of auto-filled values in a card layout for faster mobile experience), "Continue to Sign" button at bottom (Talkpush Green, sticky).
  • Screen 3 — Field Input: One field per screen (large, easy to tap). Field label, helper text, large input. Progress bar at top (e.g., "3 of 7 fields"). "Next" button (Talkpush Green). "Back" link. For dropdowns: full-screen picker. For dates: native date picker.

Risks & Mitigations

RiskImpactLikelihoodMitigation
Legal validity of signatures questioned High Low Follow ESIGN/UETA requirements precisely: consent, audit trail, tamper-evident storage. Have legal team review the Certificate of Completion format. Consider optional digital certificate (PKI) in Phase 3.
PDF rendering fidelity across devices Medium Medium Use a proven server-side PDF rendering library (e.g., pdf-lib, PDFKit, or commercial like PSPDFKit). Test across major mobile browsers. Provide "View Full PDF" fallback.
Field placement accuracy on generated PDFs High Medium Use percentage-based coordinates (not pixel) for field positions. Extensive QA with various PDF templates. Provide admin preview of generated document with sample data before publishing.
Signing link security (token guessing) High Very Low Use 256-bit cryptographically random tokens. Rate-limit invalid token attempts. Links expire. Optional identity verification for sensitive documents.
Migration from DocuSign for existing clients Medium High Run TalkSign in parallel with DocuSign initially. Provide migration tooling to recreate templates. Keep DocuSign integration as fallback for clients not ready to switch. Phase out gradually.
Mobile signing UX on low-end devices Medium Medium Optimize for low bandwidth: lazy-load PDF pages, compress images. Test on entry-level Android devices. Guided field-by-field flow avoids rendering full PDF on mobile.
